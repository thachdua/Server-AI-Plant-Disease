# iOS UI Engineering

## Overview

Build production-quality iOS user interfaces that are accessible, performant, and visually polished according to Apple Human Interface Guidelines (HIG). The goal is a UI that feels native, fluid, and built by a senior iOS engineer — not a generic Web-like interface generated by AI. This means proper use of SwiftUI modifiers, native navigation, accessible Dynamic Type, and thoughtful state management.

## When to Use

- Building new SwiftUI Views or UIKit ViewControllers
- Implementing responsive layouts for iPhone and iPad (Size Classes)
- Adding interactivity, animations, or MVVM state management
- Integrating AI model results (like CoreML/Vision) into the UI
- Fixing visual or UX issues on iOS

## Architecture (MVVM Pattern)

### File Structure

Group files by Feature/Screen, not by type:

```text
Features/
  LeafScanner/
    LeafScannerView.swift         # The SwiftUI View (UI only)
    LeafScannerViewModel.swift    # Business logic & State management
    LeafScannerComponents.swift   # Sub-views specific to this screen
  DiseaseDetail/
    DiseaseDetailView.swift
    DiseaseDetailViewModel.swift
```

### Component Patterns

**Prefer composition using small, focused Views:**

```swift
// Good: Composable and easy to read
var body: some View {
    VStack(spacing: 16) {
        HeaderView(title: "Scan Results")
        DiseaseResultCard(disease: viewModel.detectedDisease)
        ActionButtons(onRetake: viewModel.resetScanner)
    }
    .padding()
}

// Avoid: Massive View body with nested logic
var body: some View {
    VStack {
        Text("Scan Results").font(.largeTitle)
        if let disease = viewModel.disease {
            VStack {
                 Image(uiImage: disease.image)
                 // ... 50 more lines of code inline
            }
        }
    }
}
```

**Separate business/AI logic from presentation:**

```swift
// ViewModel (State & Logic)
@MainActor
final class LeafScannerViewModel: ObservableObject {
    @Published var isAnalyzing = false
    @Published var scanResult: DiseaseResult?
    
    func analyzeImage(_ image: UIImage) async {
        isAnalyzing = true
        // Call AI Model (e.g., CoreML)
        self.scanResult = await MLService.shared.predict(image)
        isAnalyzing = false
    }
}

// View (Presentation only)
struct LeafScannerView: View {
    @StateObject private var viewModel = LeafScannerViewModel()
    
    var body: some View {
        ZStack {
            CameraPreview()
            
            if viewModel.isAnalyzing {
                ProgressView("Analyzing leaf...")
            }
        }
    }
}
```

## State Management

**Choose the correct SwiftUI property wrapper:**

```text
@State            → Local, simple UI state (e.g., isExpanded, inputText)
@Binding          → Two-way connection to a parent's @State
@StateObject      → Instantiating a ViewModel (Source of truth)
@ObservedObject   → Passing an existing ViewModel to a child view
@Environment      → Reading system values (colorScheme, dismiss)
@EnvironmentObject→ Global app state (UserSession, ThemeSettings)
```

*Note: If using Swift 5.9+, prefer the new `@Observable` macro over `ObservableObject`.*

## Design System Adherence (Apple HIG)

### Avoid the "AI Web" Aesthetic on iOS

AI often writes SwiftUI as if it were writing Tailwind HTML. Avoid these patterns:

| AI Default | Why It Is a Problem on iOS | Native iOS Quality |
|---|---|---|
| Hardcoded Hex Colors (`#FF0000`) | Doesn't support Dark Mode automatically | Use Semantic colors (`.primary`, `.secondary`, `Color(.systemBackground)`) |
| Arbitrary fonts (`.font(.custom(...))`) | Breaks Dynamic Type (accessibility text sizing) | Use `.font(.headline)`, `.font(.body)`, etc. |
| Custom back buttons/headers | Breaks native swipe-to-go-back gestures | Use `NavigationStack` and `.navigationTitle()` |
| `.cornerRadius(20)` everywhere | Outdated modifier, inconsistent curves | Use `.clipShape(RoundedRectangle(cornerRadius: 16, style: .continuous))` |
| Huge arbitrary paddings (`padding(30)`) | Looks broken on smaller iPhones | Use standard `.padding()` (16pt) or multiples of 8 |

### Spacing and Layout

Use Apple's standard 8pt grid system. Don't invent values:

```swift
// Good
VStack(spacing: 8) { ... }
HStack(spacing: 16) { ... }

// Bad
VStack(spacing: 13) { ... }
```

### Typography

Always use semantic typography so the app scales with the user's Accessibility settings:

```swift
Text("Disease Name").font(.title2).fontWeight(.semibold)
Text("Confidence: 98%").font(.subheadline).foregroundColor(.secondary)
```

## Accessibility (VoiceOver & Dynamic Type)

Every native iOS component must be accessible:

### VoiceOver Modifiers

```swift
// Label interactive elements clearly
Button(action: capturePhoto) {
    Image(systemName: "camera.viewfinder")
}
.accessibilityLabel("Take photo of leaf")
.accessibilityHint("Double tap to capture image for analysis")
.accessibilityTraits(.isButton)

// Hide decorative images from VoiceOver
Image("leaf_decoration")
    .accessibilityHidden(true)
```

### Meaningful Empty and Error States

```swift
// Don't show blank screens when data is missing or failing
struct EmptyHistoryView: View {
    var body: some View {
        ContentUnavailableView(
            "No Scans Yet",
            systemImage: "leaf",
            description: Text("Take a photo of a plant leaf to detect diseases.")
        )
    }
} // Note: ContentUnavailableView is iOS 17+. Use custom VStack for iOS 16-.
```

## Loading and Transitions

Provide fluid feedback, especially when waiting for AI model inference.

```swift
// Skeleton loading using redacted
struct HistorySkeletonRow: View {
    var body: some View {
        HStack {
            Circle().frame(width: 50, height: 50)
            VStack(alignment: .leading) {
                Text("Placeholder Disease").font(.headline)
                Text("Date").font(.subheadline)
            }
        }
        .redacted(reason: .placeholder)
        .shimmering() // If using a shimmer library
    }
}

// Fluid transitions
if showResults {
    ResultCard()
        .transition(.move(edge: .bottom).combined(with: .opacity))
}
```

## Red Flags in Generated Code

- Massive `body` properties (over 100 lines).
- Using `GeometryReader` unnecessarily (it breaks standard layouts; prefer `VStack`/`HStack`/`Grid`).
- Force unwrapping optionals (`!`) in UI code.
- Hardcoded screen dimensions (`UIScreen.main.bounds`).
- Missing `@MainActor` on ViewModels that update the UI.
- Not handling safe areas (`.ignoresSafeArea()` used incorrectly).

## Verification

After building UI:

- [ ] View compiles without warnings.
- [ ] Hierarchy is broken down into small, reusable sub-views.
- [ ] Dark Mode and Light Mode both look correct (using semantic colors).
- [ ] View logic is extracted to a ViewModel (MVVM).
- [ ] Appropriate loading states are present for AI/Network tasks.
- [ ] `SF Symbols` are used for icons instead of custom SVGs where possible.
